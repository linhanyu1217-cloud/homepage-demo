【步骤 2：检查本周输入】
================================================================

扫描以下四个投递目录：

    02_待处理\A股公告\Wnn公司公告     ← 本周 A股，nn 由 REPORT_WEEK_TAG 给定
    02_待处理\港股公告\Wnn公司公告     ← 本周港股，nn 由 REPORT_WEEK_TAG 给定
    02_待处理\新闻资讯                 ← 平铺目录，允许为空
    02_待处理\研报                     ← 平铺目录，允许为空

【周次目录规则 · 硬规则】

    1. 公司公告**按周次放在子文件夹中**，命名固定为 `Wnn公司公告`：

           2026-W37  →  W37公司公告
           2026-W38  →  W38公司公告

       A股与港股**都**采用该规则。

    2. **只读本周子目录**，路径以环境变量为准：
           A股  = REPORT_IN_A
           港股 = REPORT_IN_HK

    3. **绝不扫描其他周次目录** —— 不得把上周、下周的公告混入本周。
       不得用通配符（如 `W*公司公告`）或遍历父目录来"凑"输入。

    4. **不自行拼接路径**：若 REPORT_IN_A / REPORT_IN_HK 未注入，记为
       【待人工确认】并停止处理公告，不要猜目录名。

    5. 子目录不存在或为空 → 记为「本周该市场无输入」，写入 run_log.md；
       **不报错、不退出、不阻塞其余步骤**。

【跨市场去重规则 · 硬规则】

    同一份公告可能同时出现在 A股与港股目录中（例如导出时放错位置）。
    每周都要做一次**跨目录去重**，判定顺序固定：

        1) 先比**文件名**
        2) 再比**文件大小**
        3) 条件允许时再比**文件哈希（SHA256）**

    三项都相同 → 判定为**完全重复**，标记为【忽略：跨市场重复文件】，
    **只处理一次**（本流程中一律保留 A股 一侧，忽略港股一侧的同名副本）。

    **绝对禁止**：删除、移动、重命名任何重复文件。只在**处理阶段忽略**。

    - 重复数量、重复文件路径、忽略原因 → 必须写入 run_log.md；
    - 脚本已把清单落盘到 `REPORT_DUP_CSV`（列：忽略文件路径 / 对应A股文件 /
      文件名 / 字节数 / sha256 / 判定依据 / 处理方式），直接引用，不要重算；
    - 统计口径：
          A股有效数   = REPORT_A_EFFECTIVE
          港股有效数  = REPORT_HK_EFFECTIVE
          忽略重复数  = REPORT_DUP_COUNT
    - **同名但大小或内容不同** → **不算重复**，照常处理，并在 run_log.md 中说明。

要求：
    - **只处理本周材料**（以 REPORT_START ~ REPORT_END 为窗口，
      并参考文件修改时间判断"新增"）。
    - 若某个目录为空 → 在 run_log.md 中如实记录"本周无新增"，**不要编造内容**。
    - 若全部为空 → 仍然正常完成流程，输出各文件并在 run_log.md 与
      周报更新说明.md 中写明"本周无输入材料"，然后正常结束。

【空目录处理 · 硬规则】

    02_待处理\新闻资讯 与 02_待处理\研报 **允许为空**。

    - 目录为空 → 记录「本周无输入」，写入 run_log.md；
    - **不得报错**；
    - **不得阻塞公司公告任务** —— 步骤 3/4/5/8 照常执行；
    - 对应的 本周重要资讯.md 输出「本周无新增资讯材料」，不是错误；
    - 以后再接外部资讯/研报渠道，当前状态记为「非阻塞待扩展」。

    即：新闻资讯与研报**不是**流程的前置依赖，缺失时照常产出公司公告相关交付物。

原始公告文件命名参考（历史 iFind 导出格式）：
    A股：2026-09-04：600208--衢州发展--衢州发展：总裁暨法定代表人离任的公告.pdf
   港股：港股公告文件名不含公司名，需打开 PDF 正文提取「股份代號」与公司全称。

【步骤 3：处理公司公告】
================================================================

按照「行业公司池 + 重点关注池 + 公告模板」三者结合，筛选本周地产行业重要公司公告。

覆盖范围是**整个地产行业**，不只覆盖重点公司：
    - A股：申万 2021 行业分类「房地产」
    - 港股：恒生行业分类中的地产代理 / 地产发展商 / 地产投资 /
            REITs / 物业服务及管理
    - **排除建筑业**：建筑材料 / 楼宇建造 / 重型基建 / 其他纯建筑类

三层标签的用法：
    - 行业公司池全部公司都要过一遍，不因为"不是重点"就跳过；
    - 重点关注公司优先检查；
    - 非重点公司若发生重大事件，同样进入筛选结果。

重要性判定（以"事件本身是否值得地产行业研究关注"为准）：

    优先关注 16 类：
        销售经营数据 / 中报年报业绩公告 / 盈利预警 / 拿地 / 融资 / 债务 /
        债务重组 / REITs / 回购 / 分红 / 股权变化 / 核心管理层变化 /
        重大诉讼 / 行政处罚 / 重大资产交易 / 重大经营事项

    低优先级（【硬规则】，见下）：
        董事名单与角色职能 / 普通董事变更 / 常规股东大会 / 一般授权 /
        常规换届 / 无实质变化的公告 / 金额很小且对经营影响有限的事项

【公告落点 · 硬规则】（2026-09-16 起：Word 不分类，分类只发生在 PPT 层）

    **Word 是本周公司公告的完整底稿，不设「正式版 / 备选版」。**

    只保留"值得保留"的公告，凡有研究价值的**一律收录进同一份 Word**：
        销售数据、业绩公告、盈利预警、拿地、融资、债务、REITs、分红、回购、
        股权变化、核心管理层变化、重大诉讼、行政处罚、重大资产交易，
        以及其他有研究价值的重要事项。

    **只有确无研究价值的纯程序性公告才不收录**（下列仅为示例）：
        普通股东大会通知（无实质结果）、一般授权（未实际发生）、
        无实质变化的重复公告、普通董事名单更新（无人员变动）、
        金额很小且对经营影响有限、也无趋势含义的事项。

    落点对照：
        有研究价值（16 类范围内）  →  ✅ 进 Word；再由 PPT 二次筛选决定是否进 PPT
        纯程序性、无研究价值        →  ❌ 不进 Word；不进 PPT

    **一律不得静默丢弃**：凡判定为纯程序性而不收录的公告，
    必须在 run_log.md 或 来源清单.csv 的「筛选原因」列写明"为什么没收录"。

    ⚠️ 判据是「事件本身是否值得地产行业研究关注」，**不是"上期写过"**。
       模板中出现过「董事名单与其角色和职能」这类条目，但有**人员变动**时
       才构成收录理由。

按公告类型提取要点（不机械复制原文/整张报表）：

    销售公告 → 单月销售金额及同比、单月销售面积及同比、累计金额及同比、
               累计面积及同比，必要时销售均价
    业绩公告 → 营业收入及同比、毛利/毛利率、归母净利润或核心利润及同比、
               每股盈利、分红、净负债率、重要经营指标
    拿地     → 城市、区域、项目/地块、用途、土地面积/计容面积、地价、权益比例
    融资     → 融资规模、品种、期限、利率、募集资金用途、当前审批或发行阶段
    REITs    → 项目/基金名称、底层资产、募集规模/份额、基金管理人、
               当前审批阶段、重要时间节点
    债务重组 → 涉及债务规模、支持比例、方案、当前进度、截止日期
    诉讼/处罚→ 涉及金额、占净资产比例（如有）、原因、当前进度、
               对经营、利润或上市地位的影响

【步骤 4：生成 Word 底稿（本周公司公告汇总）】
================================================================

把步骤 3 筛后**所有值得保留**的公告整合进**同一份底稿**，不做任何分类。

写入：REPORT_DIR\本周公司公告汇总.md

**这是 Word 交付物的唯一输入**，格式必须完全对齐模板：

    广发证券房地产每日新闻（YYYY.MM.DD）——李怡慧
    【公司新闻】
    【公司简称】公告事项：核心事实 + 最重要数字 + 必要进展。

规则：
    - 按自然日升序；当日无公告则整日不出现；
    - 每日标题下固定一行【公司新闻】；
    - 一条一段不换行，以句号收尾；
    - 公司名用公告中的证券简称（港股可保留繁体全称）；
    - 同一天内，重点关注公司排前面；
    - **正文要求：客观、简洁、信息密度高、数字优先、不编造数据、不写无来源判断**；
    - **不写"正式/备选""入选/落选"之类的分类标记**（分类只发生在 PPT 层）。

**不再生成**：本周公司公告正式版.md、本周公司公告备选.md。

【步骤 5：PPT 二次筛选（生成 PPT候选内容）】
================================================================

Word 是完整底稿；**PPT 才对内容做二次筛选**。

唯一基础来源（三者结合，不读原始 PDF）：
    1. 本周公司公告周报.docx
    2. 本周公司公告汇总.md
    3. 本周重要资讯.md

写入：REPORT_DIR\PPT候选内容.md

筛选原则：
    **优先 [正式入选]**：重点房企重大公告、重要销售数据、业绩、融资、REITs、
                        债务、重大资产交易、有明显行业代表性的事项、重要行业资讯。
    **[备选]**：有研究价值但优先级略低 / 页面放不下 / 与正式内容存在一定重复 /
               适合作为人工替换项。

条目块格式（**每条必须标记**，块之间空一行）：

    [正式入选] 保利发展销售同比承压，可转债与拿地同步推进。
    事实：8月签约金额150.13亿元，同比下降16.67%；1-8月累计签约金额1,650.42亿元，同比下降8.92%。
    点评：单月降幅大于累计降幅，销售压力仍存；融资与补货同步推进，资金端保持主动。

    [备选] 九龙仓置业中期派息同比增长42%，出售资产降杠杆。
    事实：……
    点评：……
    理由：为什么本期不放进 PPT（页面空间不足 / 同类内容太多 / 重要性略低 / 与现有内容重复）。

**小标题硬格式（违反会被脚本直接拒绝生成）：**
    - **不得使用任何括号**：`【】` `（）` `()` `[]` `〔〕` `《》` `「」` 一律禁止。
      ✗ 不要写 【保利发展：……】 或 （保利发展：……）
    - **必须以中文句号「。」结束**，句号后**直接接正文**，不另起一行、不再加空格。
    - 标题与正文**在同一个项目符号段落内**；标题红色加粗，正文黑色正常字重。
    - 标题**必须带公司名称**，不得只写行业概括，除非本条本身就是多家公司共同趋势。

**正文写法**：PPT 正文用**行文体例**（`同比下降16.67%`），与 Word 底稿的
    符号体例（`（同比-16.67%）`）分工不同 —— 数值完全一致，只改写法。
    百分点写「同比下降4个百分点」。绝对值、比率、排名一律照抄，不做换算。

**硬规则：**
    - **同公司合并**：同一家公司本周有多条重要事项时，优先整合为一条，标题带公司名。
      例：保利发展本周有「销售 / 可转债 / 拿地」三条，合并为
          「保利发展销售同比承压，可转债与拿地同步推进。」
      而不是拆成"保利发展销售 / 保利发展融资 / 保利发展拿地"三条。
    - **点评必须基于已经出现的数据和事实**，不能凭空扩展，不能加入没有来源支持的判断。
      点评风格：简短、客观、券商研究风格、不写空泛结论、不用营销化语言，
      尽量体现趋势、边际变化、分化、改善或压力。
      允许的表述：边际改善、降幅收窄、同比承压、增速回升、销售与利润表现分化、
                  融资环境边际改善、经营韧性较强、压力仍存、结构有所改善、后续仍需关注。
      **禁止**：无依据的乐观/悲观判断、价格目标、投资建议、
              "显著利好""强烈看好"等营销化措辞、超出原始数据支持范围的推断。
    - **条数不是固定值**：最终 4 / 5 / 6 条都可以，由每条长度、同公司是否合并、
      点评长度、页面剩余空间与可读性共同决定。**不要为了凑数或省版面而固定条数。**
    - 正式入选按重要性排序；备选**按重要性排序**（脚本可能按此顺序自动补位）。
    - **放不下时的处理顺序**（**绝不缩小字号**）：
          1) 先合并同公司内容 → 2) 再减少低优先级条目 → 3) 再压缩正文细节。
      被减下的条目转成 `[备选]` 并写明 `理由`，**不退化为丢弃**。
