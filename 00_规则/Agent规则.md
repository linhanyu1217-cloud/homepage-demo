## 〇、这份规则解决什么问题

本工作区是一个**长期运行**的「地产行业周报 Agent」，不是一次性总结。

目标：以后每周重复完成

1. 地产行业上市公司公告筛选
2. A股、港股重点房企跟踪
3. 房地产行业重点资讯筛选
4. 周报内容整理
5. 固定 PPT 页面更新
6. 后续结构化数据更新
7. 最终可由 Windows 定时拉起自动运行

**当前阶段只搭建基础设施，不注册定时任务。**

## 五、行业公司覆盖逻辑

### 5.1 覆盖范围 = 整个地产行业，不只是重点公司

**A股：** 以申万 2021 行业分类中的**房地产行业**为基础公司全集。

**港股：** 以恒生行业分类中的**地产相关公司**为基础，包括：

- 地产代理
- 地产发展商
- 地产投资
- 房地产投资信托 REITs
- 物业服务及管理

**明确排除建筑业**，包括：

- 建筑材料
- 楼宇建造
- 重型基建
- 其他纯建筑类公司

### 5.2 三层逻辑

| 层 | 名称 | 含义 |
|---|---|---|
| 第一层 | **行业全集** | 整个地产行业公司，是「监测范围」 |
| 第二层 | **历史覆盖标签** | 根据历史公告判断：是否过去做过、历史出现次数、主要公告类型 |
| 第三层 | **重点关注标签** | 重点房企拥有更高优先级 |

> ⚠️ **重点关注池不是完整行业名单。**
> **非重点公司如果发生重大事件，也必须进入正式筛选。**

三层标签的详细口径见 `00_规则\行业公司池规则.md` 与 `00_规则\重点关注池.md`。

## 六、公告模板的使用方式

### 6.1 固定模板

`01_模板\公司公告周报模板.docx`

这份文件是「**格式模板 + 历史写作样例**」。**以后每周执行公司公告任务前必须先读取。**

### 6.2 需要学习的 7 件事

1. **日期分组方式**
2. **每日标题结构**
3. **【公司新闻】栏目结构**
4. **单条公告标题方式**
5. **正文信息密度**
6. **数字表达方式**
7. **券商研究风格**

### 6.3 模板的实际结构（据 2026-09-16 实读）

```
广发证券房地产每日新闻（2026.09.04）——李怡慧
【公司新闻】
【首开股份】关于累计诉讼、仲裁事项的公告：公司新增诉讼、仲裁金额合计约7.30亿元，……
【衢州发展】总裁暨法定代表人离任公告：总裁林俊波女士因个人工作安排申请辞去总裁职务……
广发证券房地产每日新闻（2026.09.05）——李怡慧
【公司新闻】
【新城控股】关于商业不动产REITs申报发行工作进展的公告：公司申报的"……"于2026年9月3日获中国证监会注册批复……
```

**结构要点：**

| 要素 | 规则 |
|---|---|
| 日期标题 | `广发证券房地产每日新闻（YYYY.MM.DD）——李怡慧` |
| 栏目头 | 每日标题下固定一行 `【公司新闻】` |
| 条目格式 | `【公司简称】公告标题：核心事实 + 最重要数字 + 必要进展。` |
| 条目结尾 | 以句号收尾，一条一段，**不换行** |
| 日期顺序 | 按自然日升序排列；**当日无公告则整日不出现** |
| 公司名 | 使用**公告中的证券简称**（港股可保留繁体全称） |

### 6.4 禁止事项

- ❌ **不要机械复制模板里的旧公司或旧数字**；
- ❌ 不要把模板中的历史内容当作本周内容；
- ❌ 不要修改 `01_模板` 中的原文件。

### 6.5 单条公告原则

> **【公司名称】公告事项：核心事实 + 最重要数字 + 必要进展。**

风格要求：

- 客观
- 简洁
- 高信息密度
- 数字优先
- 少形容词
- 不写营销化措辞
- **不写没有来源支撑的判断**

## 七、公告重要性筛选规则

### 7.1 优先关注（16 类）

1. 销售经营数据
2. 中报、年报、业绩公告
3. 盈利预警
4. 拿地
5. 融资
6. 债务
7. 债务重组
8. REITs
9. 回购
10. 分红
11. 股权变化
12. 核心管理层变化
13. 重大诉讼
14. 行政处罚
15. 重大资产交易
16. 重大经营事项

### 7.2 Word 不收录的公告（极低价值、纯程序性）

**Word 是本周公司公告的完整底稿**，收录面本身已经很宽；只有下列**确无研究价值**的
公告才不纳入 Word。包括但不限于：

- 普通股东大会通知（仅有会议时间、议案清单，无实质结果）
- 一般授权（如常规性的一般性授权、回购授权本身未发生）
- 无实质变化的重复公告（同一事项的例行进展，且本期无新增量）
- 普通董事名单更新（董事名单与角色职能，无人员变动）
- 金额很小、对经营影响有限且无趋势含义的事项

### 7.3 Word 应尽量完整收录的范围

销售数据、业绩公告、盈利预警、拿地、融资、债务、REITs、分红、回购、
股权变化、核心管理层变化、重大诉讼、行政处罚、重大资产交易，以及其他
有研究价值的重要事项（详见第 7.1 节 16 类）。

> **判据是「事件本身是否值得地产行业研究关注」，不是"上期写过"。**
> 模板中**出现过**「董事名单与其角色和职能」这类条目（恒隆集团、恒隆地产）——
> 说明历史成品的体例并不绝对排斥它，但**有人员变动**时才构成收录理由。

### 7.4 落点规则（Word 不分类，分类只发生在 PPT 层）

| 情形 | Word（`本周公司公告周报.docx`） | PPT 正式入选 | PPT 备选 |
|---|---|---|---|
| 第 7.3 节范围内的重要公告（重点房企重大公告、重要销售数据、业绩、融资、REITs、债务、重大资产交易、有明显行业代表性） | ✅ 进 | 择优进 | 未择优的进 |
| 第 7.3 节范围内的其他公告 | ✅ 进 | 视当期版面 | ✅ 进 |
| 第 7.2 节（纯程序性） | ❌ 不进 | ❌ 不进 | ❌ 不进 |

**Word 不再区分「正式版 / 备选版」**，本周所有值得保留的公告整合进**同一份**
文档；正式 / 备选的区分**只发生在 PPT 二次筛选**（见第 10.8 节）。

> ⚠️ **不得"静默丢弃"** —— 凡被判断为纯程序性而不进 Word 的公告，
> 必须在 `run_log.md` 或 `本周公司公告来源清单.csv` 的「筛选原因」列留下
> 「为什么没收录」的记录，供人工复核。

### 7.5 判定原则

- **重点关注公司优先检查**；
- 但**重要性最终以「事件本身是否值得地产行业研究关注」为准**。

## 八、不同公告类型的摘要规则

### 8.1 销售公告

优先提取：单月销售金额、**同比**、单月销售面积、**同比**、累计销售金额、累计同比、累计销售面积、累计同比，必要时**销售均价**。

### 8.2 业绩公告

优先提取：营业收入、同比、毛利/毛利率、归母净利润或核心利润、同比、每股盈利、分红、净负债率、重要经营指标。

> **不要机械复制整张财务报表。**

### 8.3 拿地

优先提取：城市、区域、项目/地块、用途、土地面积/计容面积、地价、权益比例。

### 8.4 融资

优先提取：融资规模、品种、期限、利率、募集资金用途、当前审批或发行阶段。

### 8.5 REITs

优先提取：项目/基金名称、底层资产、募集规模/份额、基金管理人、当前审批阶段、重要时间节点。

### 8.6 债务重组

优先提取：涉及债务规模、支持比例、方案、当前进度、截止日期。

### 8.7 诉讼/处罚

优先提取：涉及金额、占净资产比例（如有）、原因、当前进度、对经营、利润或上市地位的影响。

## 九、数字纪律

### 9.1 所有数字必须能回查原始来源

### 9.2 严格区分

**符号体例（Word 底稿 / md / CSV —— 求信息密度）**

| 概念 | 写法 |
|---|---|
| 同比 | `+8.0%` / `-12.5%` |
| 百分点 | `+3.2pct` / `-1.5pct` |

**行文体例（PPT 页 —— 求可读性，与模板自带样例一致）**

| 概念 | 写法 |
|---|---|
| 同比 | `同比增长8.0%` / `同比下降12.5%` |
| 环比 | `环比增长3.1%` / `环比下降6.4%` |
| 百分点 | `同比提升5.3个百分点` / `同比下降0.8个百分点` |

> 两套体例**只改写法，不改数值**：同一事项在 `本周公司公告汇总.md` 与
> `PPT候选内容.md` 里的数字必须完全一致。PPT 用行文句式是为了在幻灯片上读得通
> （`（同比-16.67%）` 这种括号密集写法适合 Word 底稿，不适合 10pt 正文）。
> 依据：模板自带样例即为此体例 ——「新鸿基地产全年基础溢利稳步增长，租赁业务保持韧性。
> 2025/26财年实现基础溢利228.50亿港元，同比增长4.6%……」

**不变的部分**：绝对值（亿元 / 亿港元 / 港元 / 万平方米）、比率值（占比、负债率、
毛利率、票面利率）、排名、期限等，两处写法完全一致，不做任何换算或取整。

### 9.3 禁止

- ❌ 猜同比
- ❌ 猜环比
- ❌ 猜证券代码
- ❌ 猜公告日期
- ❌ 猜公司所属市场
- ❌ 混淆亿元/万元
- ❌ 混淆平方米/万平方米
- ❌ 混淆人民币/港元
- ❌ 混淆百分比/百分点

### 9.4 兜底

> **如果原始公告没有披露，就不要补。**
> 无法确认的一律标 **【待人工确认】**。

### 10.5 PPT 页生成规则（2026-09-16 使用者确认）

#### 10.5.1 模板事实（实测）

`01_模板\房地产周报PPT模板.pptx` —— **整个文件只有 1 页**（`ppt/slides/slide1.xml`，无其他 slide）。

| 项 | 实测值 |
|---|---|
| 页数 | **1 页** |
| 页面主题 | 标题区 `行业动态` / `地产`，正文为**重点公司公告 / 重点资讯** |
| 条目数（模板现状） | **6 条** |
| 正文字号 | **10pt**（`sz=1000`） |
| 条目结构 | **加粗导语句**（公司名＋事件概括，含轻量定性）＋ **不加粗的数据句** |
| 条目样例 | **新鸿基地产全年基础溢利稳步增长，租赁业务保持韧性。** 2025/26财年实现基础溢利228.50亿港元，同比增长4.6%…… |

#### 10.5.2 硬规则

1. **不需要页码识别** —— 模板只有 1 页；
2. **不需要多页来源映射**；
3. **每周只复制这一页模板生成新 PPT**（复制后改副本，**永不覆盖 `01_模板` 原文件**）；
4. **根据本周内容长度决定放几条**（模板基线 6 条，**条数不是固定值**：
   4 / 5 / 6 条都可，由每条长度、同公司是否合并、点评长度、页面剩余空间与
   可读性共同决定）；
5. **优先保持模板原字号、字体、文本框位置和版式**；
6. **内容放不下时：先合并同公司内容 → 再减少低优先级条目 → 再压缩正文细节，
   绝不缩小字体**；
7. **一页无法容纳所有正式入选事项时，只保留最重要的**（按 `PPT候选内容.md` 的
   排列顺序，排在后面的先落选），其余转入 `[备选]`，不退化为丢弃；
8. **版面自适应（2026-09-16 新增）** —— 正式入选全部入版后若**下半页仍有明显大块
   空白**，且备选池里还有内容，则按重要性**补入**；页面已较满则不补。

   | 情形 | 处理 |
   |---|---|
   | 下方空余明显大 | 可尝试增加 1 条（不足则继续，直到安全线） |
   | 页面已较满 | **不再增加** |
   | 加入后拥挤 / 溢出 / 页面过满 | **撤回**该条新增内容 |

   硬约束：新增内容**从备选池按重要性（文件内顺序）挑选，不跳级**；
   加入后必须保持**原字号、原行距、可读性**；**不允许为了多放内容明显缩小字体**。
   脚本实现阈值：行占用 ≥ 78% 视为「已较满」，补位后**不得超过 92%**（留 8% 余量
   吸收折行估算误差）。**优先保持清晰，不追求固定条数。**

#### 10.5.3 页面写法（2026-09-16 修订：**标题不加任何括号，以句号结尾**）

每条内容 = **红色加粗小标题** + **黑色事实正文** + **1-2 句点评**，
**全部同处一个项目符号段落**：

```
<公司名称><核心结论，……。><事实与数据，……。><点评，……。>
└──── run[0] 红色加粗 ────┘└──── run[1] 黑色不加粗 ────────┘
```

**正确示例：**

> 保利发展销售同比承压，可转债与拿地同步推进。8月签约金额150.13亿元，同比下降16.67%；
> 1-8月累计签约金额1,650.42亿元，同比下降8.92%。公司拟发行不超过50亿元可转债，
> 并新增东莞南城项目。单月降幅大于累计降幅，销售压力仍存；融资与补货同步推进，
> 资金端保持主动。

**小标题硬格式（违反即拒绝生成）：**

| # | 规则 |
|---|---|
| 1 | **不得使用任何括号** —— `【】` `（）` `()` `[]` `〔〕` `《》` `「」` 一律禁止 |
| 2 | **必须以中文句号「。」结束** |
| 3 | 句号后**直接接正文**，不另起一行、不再加空格 |
| 4 | 标题与正文**在同一个项目符号段落内** |
| 5 | 标题**红色加粗**（沿用模板 `run[0]` 的 `C00000` + 加粗 + 10pt，脚本不改配色） |
| 6 | 正文**黑色、正常字重**（`run[1]` 起） |
| 7 | 标题**必须带公司名称**，不得只写行业概括，除非本条本身就是多家公司共同趋势 |

❌ **不要出现**：`【保利发展：……】`、`（保利发展：……）` 等任何带括号写法。

- **正文**为事实与数据，**黑色不加粗**，写法同第 9 节 **行文体例**
  （`同比下降16.67%`，而非 `（同比-16.67%）`）。
- **点评**接在正文最后（**不另起一段**），1-2 句，**只能从已出现的数据推导**；
  禁用「明显利好」「强烈看好」「建议买入」「目标价」等营销化 / 投资建议措辞
  （脚本内置 `BANNED_WORDS` 词表，命中即校验不通过）。

#### 10.5.4 二次筛选与内容取舍

- PPT **不做** Word 正式版/备选版的搬运，而是**基于下列来源二次筛选**：
  1. `本周公司公告周报.docx`
  2. `本周公司公告汇总.md`
  3. `本周重要资讯.md`
- 结果写入 `PPT候选内容.md`，**每条必须标记** `[正式入选]` 或 `[备选]`：
  - **`[正式入选]`** —— 真正放进本周 PPT 的内容。优先序：重点房企重大公告、
    重要销售数据、业绩、融资、REITs、债务、重大资产交易、有明显行业代表性的事项、
    重要行业资讯。
  - **`[备选]`** —— 有研究价值但页面空间不足、同类内容太多、重要性略低、
    或与正式内容重复而本期未放入；**必须写 `理由`**，作为人工替换项。
- **同公司合并**：同一家公司本周有多条重要事项时优先整合为一条。
  例：保利发展本周有「销售 / 可转债 / 拿地」三条，合并为
  `保利发展销售同比承压，可转债与拿地同步推进。`，
  **不要拆成三条**。合并后的小标题同样受 10.5.3 括号禁令约束
  （**不写** `【保利发展：……】`）。
  脚本用「本周公司简称最长前缀匹配」查出每条的主体公司，同公司重复出现即校验不通过。
- **条数按行预算决定，不是固定值**（实测预算 21 行）：正式入选先全部入版，
  再由 10.5.2 第 8 条的**版面自适应**决定是否从备选池补位。
- 落选的重要事项**不退化为丢弃**，仍保留在 `本周公司公告汇总.md` / 周报 .docx 与
  `PPT候选内容.md` 的 `[备选]` 中。

#### 10.7.2 Word 排版规则（2026-09-16 使用者确认：**所有层级统一一行空行**）

> **分页规则见 §10.7.3**（每个日期块另起一页）。两者并存：分页由段落属性实现，
> 空行由段前间距实现，**全文仍然一个空段落都没有**。

| # | 规则 |
|---|---|
| 1 | 每日标题之后空一行 |
| 2 | `【公司新闻】` 小标题**前后各**空一行 |
| 3 | 每条公司公告之间空一行 |
| 4 | 日期块与下一个日期块之间空一行 |
| 5 | **不连续出现两行以上空白** |
| 6 | 不把多个公告紧贴在一起 |

**实现方式（关键）**：**不插入任何空段落**，空行一律由**段前间距**
`GAP_TWIPS = 260`（= 13pt ≈ 11pt 正文一行高）实现：

- 每个段落 `w:spacing w:before="260" w:after="0"`，全文第一段 `before="0"`
  （避免顶部凭空多一行）；
- 260 twips **正是模板日标题自带的分节日距**（`<w:spacing w:before="260" w:after="260">`），
  不是自造数字 —— 因此日标题与正文天然同款；
- 日标题的 `line=416 auto` / `keepNext` / `keepLines` **原样保留**（只改 before/after）；
- ⚠️ **`List Paragraph` 样式自带 `<w:contextualSpacing/>`**，会**吞掉相邻同款段落之间的
  间距** —— 条目段落必须显式写 `<w:contextualSpacing w:val="0"/>` 覆盖，
  否则公告会全部粘成一片。这是最容易踩的坑。
- 表格不参与段前间距，表格上方那一行由**上一段的段后间距**补
  （`Renderer.gap_after_last`）。

**段落文字格式**：每条公告为 `【公司名称】公告事项：正文`，
正文要求**客观、简洁、信息密度高、数字优先、不编造数据、不写无来源判断**。

#### 10.7.3 分页规则（2026-09-16 使用者确认：**每个日期块另起一页**）

**一个日期 = 一个日期块；进入新日期 → 先分页，再从新的一页顶部开始陈列当天内容。**

| # | 规则 |
|---|---|
| 1 | 日期块的固定结构：日期标题（`广发证券房地产每日新闻（YYYY.MM.DD）——李怡慧`）→ `【公司新闻】` → 当日条目 `1.` `2.` `3.` … |
| 2 | **日期一变就在新日期标题前分页**：新日期从新的一页**顶部**开始 |
| 3 | 新日期标题**不得落在上一页末尾** |
| 4 | **第一页不加分页符**（它本来就在页首） |
| 5 | **同一天的公告连续排列，绝不逐条分页** |
| 6 | 每条公告之间仍保留**一行视觉空行**（`GAP_TWIPS = 260`，见 §10.7.2） |
| 7 | 日期标题、`【公司新闻】`、正文之间继续保持**一行视觉间距** |
| 8 | 某天公告多时可**自然跨页**：跨页后继续当天的公告，**不重复日期标题** |
| 9 | **不得用大量空行模拟分页**，必须用**真正的 Word 分页** |
| 10 | 模板原有的**字体 / 字号 / 编号 / 页边距 / 页眉页脚 / 段落样式**一律保持 |

**实现方式（关键）**：日期标题段落写入 `<w:pageBreakBefore/>`（段落属性「段前分页」）。

- **为什么不用手工分页符 `<w:br w:type="page"/>`**：Word 在"本段已经位于页首"时会
  **自动忽略** `pageBreakBefore`；而手工分页符落在页首时会真的翻出一页**空白页**。
  两者都是 Word 原生分页、都不靠空行，但前者不会产生空白页，所以选它。
- 它只是**段落属性**：不新增 run、不新增段落、不产生任何可见字符，
  段落的文字 / 字体 / 编号 / 间距**全部不受影响**（这正是规则 10 的落实方式）。
- 分页与"一行空行"**并存**：全文仍然**一个空段落都没有**，空行只由 `w:spacing` 产生。
- 日期块的识别：标题**含「每日新闻」且含日期**（模板写法），**或**标题**就是日期本身**
  （`## 2026.09.04`）。刻意**不**把「含日期但另有主题」的章节标题
  （如 `## 2026年半年度业绩`）当成日期块，否则会凭空多插一个分页。
- 因此 `本周重要资讯.docx` 这类**没有日期块**的文档，分页符数 = 0，行为与从前完全一致。

> **实测（Word COM 只读打开实测，非仅解析 XML）**：W37 文档 5 个日期块 → 4 个分页符，
> 各块起始页依次为 **1 / 2 / 4 / 5 / 7**，共 **9 页**；
> 09-07 占 2–3 页、09-09 占 5–6 页、09-10 占 7–9 页（当天公告多，自然跨页，未重复日期标题）；
> 无空白页（1+2+1+2+3 = 9）。分页符**全部**落在日期标题上，条目段落无一被分页。

> ⚠️ **模板没有页眉页脚**（实测：`word/` 下无 `header*.xml` / `footer*.xml`，
> `sectPr` 里 `headerReference` / `footerReference` 各 0 个）。
> 因此规则 10 里的"保持页眉页脚"在本模板下等于**什么都不做**；脚本**不会自己加**——
> 若需要页码之类的页眉页脚内容，须由使用者明确要求后再动。
> 已登记为待人工确认事项（见 §十三）。

> **只重做 Word 周报时**用 `--only 汇总`，避免连带重写 `本周重要资讯.docx`。

#### 10.7.5 自带校验（每次生成后自动跑）

| 检查 | 内容 |
|---|---|
| 包完整性 | `zip` 可读、`document.xml` / `styles.xml` / `numbering.xml` 齐全 |
| 内容一致 | 按 `body` **真实子元素顺序**（含表格落点）与 md **逐条逐序**比对，任一差异即 FAIL |
| 条目格式 | 每条公告必须是 `List Paragraph` **且**带 `w:numPr`（防"模板体"行被当成普通段落而丢编号） |
| **空行副作用** | **正文段落里不得出现任何空段落**（空行只能由 `w:spacing` 产生） |
| **间距统一** | 每段 `before` = 260（首段 0）且 `after` = 0，逐段核对 |
| **粘段防护** | 条目段落必须带 `<w:contextualSpacing w:val="0"/>` |
| **分页数量** | 带「段前分页」的段落数必须 = md 里的日期块数 − 1（首个日期块不加） |
| **分页落点** | 每个分页符必须落在**日期块标题**上；条目段落上出现分页符即 FAIL |
| **首块不分页** | 首个日期块若带段前分页即 FAIL |
| **分页非空行** | 不得同时存在分页符与空段落（防止分页其实是拿空行凑的） |
| 标题格式 | 每个日期/章节分组标题必须是 **16pt 加粗** |
| 编号引用 | 正文引用的 `numId` / `abstractNumId` 必须都能解析，不得悬空 |
| **模板保真** | `styles.xml`（字体/字号/段落样式）、`header*/footer*`（页眉页脚）、`w:sectPr`（纸张/页边距）、模板原有的全部 `abstractNum`（编号格式）逐项比对，语义不同即 FAIL |
| 模板未变 | 生成后再算一次模板 `sha256` |

> **模板保真为什么不能比对字节**：`python-docx` 存盘时会重排 XML 序列化，
> 字节必然不同（`[Content_Types].xml` 的 `Override` 顺序也会变），但那不代表内容被改。
> 因此改为**逐项语义比对**：`styles.xml` 用 C14N 规范化后比、
> `header*/footer*` 要求逐字节相同、`w:sectPr` 与每个 `abstractNum` 各自规范化后比。

## 十五、自动检查与触发（2026-09-16 建立，脚本 `脚本\检查并触发周报.ps1`）

### 15.1 为什么不是「每小时轮询」

使用者的实际工作习惯是：**通常在周五上午或下午**从 iFind 下载并整理本周公司公告。
因此不需要长时间每小时检查——只在周五白天按固定频率看一眼即可。

### 15.2 自动检查时间

| 项 | 值 |
|---|---|
| 执行日 | **每周五** |
| 开始时间 | **09:00** |
| 检查频率 | **每 15 分钟一次** |
| 检查截止 | **20:00**（**截止时刻那一次仍会执行**——它是当天最后一次机会；20:01 起才算过点） |
| 实际触发时刻 | 09:00 / 09:15 / 09:30 / 09:45 …… 19:45 / 20:00 |
| 周六 | **不再常规轮询** |

### 15.3 触发条件（**全部满足**才启动 `脚本\run_weekly.ps1`，任一不满足即结束本次检查）

每次检查只做**本地轻量判断**，共 12 项：

| # | 检查项 | 不通过时的行为 |
|---|---|---|
| 1 | 今天是周五（或人工补跑时显式给了 `-AnyDay`） | 结束 |
| 2 | 当前时间未过 20:00 | 结束，日志记「已过当日截止时间」 |
| 3 | A股侧存在 `Wnn公司公告` 周次目录 | 结束 |
| 4 | 港股侧存在 `Wnn公司公告` 周次目录 | 结束 |
| 5 | 两侧的**最新周次是同一个** | 结束 |
| 6 | 该最新周次 = 本周目标周次（最近一个已结束的周五所属 ISO 周） | 结束（防止误跑旧周次） |
| 7 | 两侧目录都**非空** | 结束 |
| 8 | 两侧所有文件**最近 5 分钟都没有变化** | 结束（正在复制 PDF 时不触发） |
| 9 | 该周次**尚未完成**（无 `05_输出\YYYY-Wxx\done.flag`） | 结束 |
| 10 | 该周次**未被人工叫停**（无 `04_工作区\locks\YYYY-Wxx.manual`） | 结束 |
| 11 | 该周次**没有正在运行**（无有效 PID 的 `.running` 锁） | 结束（失效锁视为未运行） |
| 12 | 自动尝试次数**未达上限**（默认 2 次） | 结束 |

### 15.4 文件稳定窗口：**5 分钟**（由原设计的 10 分钟收紧）

使用者在周五会**连续往文件夹里复制 PDF**。因此判定口径为：
**A股与港股两个周次目录中的全部文件，最近 5 分钟内都没有新增或修改**，才认为本周输入准备完成。
（参数 `-StableMinutes`，默认 5，可临时覆盖。）

### 15.5 成功 / 失败 / 上限

| 情形 | 行为 |
|---|---|
| **成功** | 写入 `05_输出\YYYY-Wxx\done.flag`。当天后续 15 分钟检查即使继续被拉起，也**发现 done.flag → 立即退出 → 不启动 Claude → 不调用 API**。**同一周只允许正式运行一次** |
| **失败** | **不创建 done.flag**，保留日志 / 中间产物 / 错误信息；下一次 15 分钟检查可以再试 |
| **连续失败 2 次** | 创建 `04_工作区\locks\YYYY-Wxx.manual`，**之后停止自动尝试**，等待人工检查 |
| **人工恢复** | 删除对应 `.manual`，或直接人工执行 `脚本\run_weekly.ps1 -Week YYYY-Wxx` |

> ⚠️ **尝试次数先加 1 再启动**：即使运行中途崩溃也算消耗一次，避免无限重试。
>
> ⚠️ **`run_weekly.ps1` 退出码 0 不等于产出齐全**——它自身在缺产出时仍以 0 退出。
> 因此调度器在写 `done.flag` 前会**自行核对 8 个交付物是否齐备**，缺任何一个即判为失败、不写 done.flag。

### 15.6 周五 20:00 仍未准备完成

若截至周五 20:00 出现：A股目录缺失 / 港股目录缺失 / 某一边为空 / 两侧周次不一致 / 文件仍未稳定，
则**当天不运行 Agent**，只在日志记录：

```
【本周输入未准备完成，自动整理未触发】
```

**不自行抓取替代数据。** 使用者可之后手动执行 `.\脚本\检查并触发周报.ps1`。

### 15.7 ★ 检查过程不得调用大模型（硬约束）

1. `检查并触发周报.ps1` **从不读取 `.env`** —— 进程里根本没有 API Key 可用；
   Key 只由 `run_weekly.ps1` 在被启动的那一刻自行加载。
2. 脚本内**不含任何网络调用**（`Invoke-WebRequest` / `Invoke-RestMethod` / `curl` / `wget` /
   `Start-BitsTransfer` / `WebClient` 一律没有），只读本地文件系统。
3. 全脚本**只有一处子进程调用点**（启动 `run_weekly.ps1`），且位于 `-DryRun` 提前返回**之后**。
4. 未满足触发条件的路径下，**Agent 启动次数实测为 0**（见第 15.9 节测试）。

### 15.9 日志与状态文件

| 路径 | 用途 |
|---|---|
| `日志\watcher_YYYYMMDD.log` | 每次检查的逐项结论（按天追加） |
| `04_工作区\locks\YYYY-Wxx.running` | 运行锁，内含 PID 与起始时间；PID 已死即视为失效锁 |
| `04_工作区\locks\YYYY-Wxx.attempts` | 已消耗的自动尝试次数（整数） |
| `04_工作区\locks\YYYY-Wxx.manual` | 连续失败达上限后的人工介入标记 |
| `05_输出\YYYY-Wxx\done.flag` | 本周已完成，此后不再自动运行 |

退出码：`0` = 检查正常结束（触发或不触发都算）；`1` = 检查自身出错或 `run_weekly.ps1` 失败。
**「未触发」不是错误**，因此不会让计划任务显示为失败。
