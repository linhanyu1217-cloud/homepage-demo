# 地产公司公告 Agent · 规则

本文件是 Agent 的**规则总纲**，与 `00_配置\任务卡.txt` 配套：
任务卡讲「这周要做什么、按什么顺序做」，本文件讲「判定口径是什么」。

> 历史沿革：本文件整合自旧版四份规则
> （工作地图、Agent规则、行业公司池规则、重点关注池）。
> 旧版规则文件在个人版中已归档保留，**未被删除**。

## 1. 公告筛选逻辑

### 1.1 覆盖范围

覆盖**整个地产行业**，不只覆盖重点公司：

- **A股**：申万 2021 行业分类「房地产」
- **港股**：恒生行业分类中的地产代理 / 地产发展商 / 地产投资 / REITs / 物业服务及管理
- **排除建筑业**：建筑材料 / 楼宇建造 / 重型基建 / 其他纯建筑类

### 1.2 三层标签的用法

| 层 | 作用 |
|---|---|
| 行业公司池 | **全部公司都要过一遍**，不因为「不是重点」就跳过 |
| 重点关注池 | 优先检查 |
| 非重点公司 | 若发生重大事件，同样进入筛选结果 |

### 1.3 优先关注的 16 类事件

销售经营数据 / 中报年报业绩公告 / 盈利预警 / 拿地 / 融资 / 债务 / 债务重组 /
REITs / 回购 / 分红 / 股权变化 / 核心管理层变化 / 重大诉讼 / 行政处罚 /
重大资产交易 / 重大经营事项

### 1.4 低优先级（【硬规则】）

董事名单与角色职能 / 普通董事变更 / 常规股东大会 / 一般授权 / 常规换届 /
无实质变化的公告 / 金额很小且对经营影响有限的事项。

⚠️ 判据是「**事件本身是否值得地产行业研究关注**」，**不是「上期写过」**。
模板中出现过「董事名单与其角色和职能」这类条目，但有**人员变动**时才构成收录理由。

### 1.5 一律不得静默丢弃

凡判定为纯程序性而不收录的公告，必须在 `run_log.md` 或来源清单的
「筛选原因」列写明**为什么没收录**。

## 2. Word 生成规则

- **Word 是本周公司公告的完整底稿，不设「正式版 / 备选版」，不做分类。**
  （分类只发生在 PPT 层。凡有研究价值的一律收录进同一份 Word。）
- 内容为**完整的公司公告摘要**，不机械复制原文、不整张报表照搬。
- **按日期分块**：同一天一个块，块内按公司排列。
- **真分页**：使用 Word 真正的分页符，不是空行堆出来的假分页。
- **同一天允许自然跨页**，不为凑整页而强行拆分或挤压。
- **保留模板的字体、字号、页边距、页眉页脚、编号**——只换文字，不动版式。
- 修改模板时必须**先复制模板再改副本**，**永不覆盖 `01_模板\` 中的原文件**。
- 写作体例：Word 用**符号体例**（`（同比-16.67%）`），PPT 用**行文体例**
  （`同比下降16.67%`）。两者**数值完全一致**，只改写法。

按公告类型提取要点：

| 类型 | 要提取什么 |
|---|---|
| 销售公告 | 单月销售金额及同比、单月销售面积及同比、累计金额及同比、累计面积及同比，必要时销售均价 |
| 业绩公告 | 营业收入及同比、毛利/毛利率、归母净利润或核心利润及同比、每股盈利、分红、净负债率、重要经营指标 |
| 拿地 | 城市、区域、项目/地块、用途、土地面积/计容面积、地价、权益比例 |
| 融资 | 融资规模、品种、期限、利率、募集资金用途、当前审批或发行阶段 |
| REITs | 项目/基金名称、底层资产、募集规模/份额、基金管理人、当前审批阶段、重要时间节点 |
| 债务重组 | 涉及债务规模、支持比例、方案、当前进度、截止日期 |
| 诉讼/处罚 | 涉及金额、占净资产比例（如有）、原因、当前进度、对经营、利润或上市地位的影响 |

## 3. PPT 生成规则

### 3.1 总纲

**PPT 只保留最重要的信息。** PPT 不是 Word 公告汇总，**不做「完整收录」**。
每条都必须值得占用**约 3 行**版面。

- **优先 [正式入选]**：重点房企重大公告、重要销售数据、业绩、融资、REITs、
  债务、重大资产交易、有明显行业代表性的事项、重要行业资讯。
- **[备选]**：有研究价值但优先级略低 / 页面放不下 / 与正式内容存在一定重复 /
  适合作为人工替换项。

### 3.2 每条约 3 行（硬约束）

- 一条 = 小标题 + 事实 + 点评，**合计约 3 行、不超过 207 个汉字**；
- **先按此长度写**，不要把长段落丢给脚本压；
- 确实写长了，脚本会**从末尾按分句**压缩并留痕，但那是兜底，不是常规；
- **绝对不要用缩小字号来容纳长内容。**

### 3.3 小标题硬格式（违反会被脚本直接拒绝生成）

- **不得使用任何括号**：`【】` `（）` `()` `[]` `〔〕` `《》` `「」` 一律禁止。
  不要写 `【保利发展：……】` 或 `（保利发展：……）`。
- **标题必须单独成行、不得另起一行写正文**：标题与正文在**同一个项目符号段落内**。
- **标题后的中文句号**：必须以中文句号「。」结束，**句号后直接接正文**，
  不另起一行、不再加空格。
- **配色与字重**：标题**红色加粗**，正文**黑色正常字重、紧接其后**。
- **标题必须带公司名称**，不得只写行业概括，除非本条本身就是多家公司共同趋势。
- **标题必须简短**：不超过**半行**（≈ 34 个汉字）。写「公司名 + 最值得关注的结论」，
  不写公文式事由。例：

      ✗ 华发股份发布2026年8月销售经营情况暨土地储备情况相关公告。
      ✓ 华发股份销售边际变化，投资端保持动作。

### 3.4 同公司公告合并（默认动作）

同一家公司本周有多条重要事项时，**一律优先整合为一条**，
而不是等到版面不够才合并，标题带公司名。

    例：保利发展本周有「销售 / 可转债 / 拿地」三条，合并为
        「保利发展销售同比承压，可转债与拿地同步推进。」
    而不是拆成「保利发展销售 / 保利发展融资 / 保利发展拿地」三条。

**合并后仍需控制在约 3 行内。**

### 3.5 点评的边界

点评**必须基于已经出现的数据和事实**，不能凭空扩展，
不能加入没有来源支持的判断。点评**只用 1 句**，简短、客观、券商研究风格。

- **允许**：销售端仍承压、降幅有所收窄、经营表现保持韧性、利润端仍有压力、
  融资环境边际改善、投资端保持积极、结构有所改善、
  现金流表现相对稳健、后续仍需关注销售修复。
- **禁止**：强烈看好、显著利好、建议买入、目标价、
  超预期（除非有明确一致预期依据）、无数据支持的主观判断、
  超出原始数据支持范围的推断。

### 3.6 重要信息优先

- **条数不是固定值**：由行预算（21 行）与每条长度共同决定。
  正常情况 5 条 × 3 行 = 19 行（90%）较为合适；6 条 × 3 行 = 23 行会**溢出**。
  **不要为了凑数或省版面而固定条数。**
- 正式入选按重要性排序；备选**按重要性排序**（脚本可能按此顺序自动补位）。

### 3.7 版面自适应（**绝不缩小字号**）

版面不足时，处理顺序**固定**：

    1) 先减少低优先级内容 → 2) 再压缩次要信息 →
    3) 再合并同公司公告   → 4) 最后才减少条目数

被减下的条目转成 `[备选]` 并写明 `理由`，**不退化为丢弃**。

反之，页面底部**还有明显空白** → 可从备选**增加 1 条**重要公告；
版面**已经接近满** → **不要硬塞**。

## 4. 港股繁体转简体

港股公告原文常为繁体。**所有面向最终阅读者的中文输出统一转简体。**

**必须转：**
1. `本周公司公告汇总.md`
2. `本周公司公告周报.docx`
3. `PPT候选内容.md`
4. 最终房地产周报 PPT
5. 其他面向最终阅读者的中文输出

**不转**（对照层，保留公告原文，便于与原始文件逐字对齐）：
- `03_个人资料\行业公司池.csv` —— 保留公告原文繁体全称
- `本周公司公告来源清单.csv` —— 保留公告原文

**只做字形转换，不改变原意：**

    ✅ 繁体字形 → 简体字形
    ❌ 不改公司名称的官方识别
    ❌ 不改数字 / 金额 / 百分比 / 日期 / 股票代码
    ❌ 不改专有英文缩写（REITs、PDFI、EBITDA、H股…）
    ❌ 不对公告事实进行自行扩写、缩写或改写

    例：「股東應佔溢利」→「股东应占溢利」
        「本集團」→「本集团」
        「截至二零二六年六月三十日止」→ 不变（这些字形本来就相同）

**实现（零依赖，不得安装新包）：**
`internal\zh_convert.py` 用 Windows 自带的 `LCMapStringW`
（`LCMAP_SIMPLIFIED_CHINESE`）做**逐字符映射**，不联网、不装 opencc / zhconv。
因为是逐字符映射，数字、金额、百分比、代码、英文天然不会被碰。

> 已知边界：Windows 自带的映射表漏掉了 `後→后`、`於→于` 两个字，
> `zh_convert.py` 里用一张补充表兜住，并同时把这两个字加进粗筛集合。

## 5. 安全边界（违反即停止）

1. 历史实习资料**默认只读**；不得删除、移动、重命名、覆盖历史实习文件。
2. 所有新生成文件**只能写入本 Agent 工作区**内的
   `05_输出\`、`04_工作区\`、`日志\`、`发行版\`。
3. 修改模板时必须**先复制模板、再修改副本**；**不直接覆盖 `01_模板\` 中的原文件**。
4. **不删除、不移动待处理公告**；只读扫描。
5. 不访问与任务无关的个人目录。
6. 不自动上传任何文件；不自动发送邮件。
7. 不执行危险的系统命令；不改注册表；不改系统代理。
8. **不打印、不记录、不写入任何 API Key 或令牌。
   日志中禁止出现 `.env` 内容、API Key、GitHub Token、其他密钥。**
9. **不自动安装软件**：不执行 `pip install`、不执行 `npm install`。
   缺依赖只提示「请自行执行 `pip install -r requirements.txt`」。
10. 不注册 Windows 计划任务（`install-watcher` 需用户确认后才注册）；
    不自动修改正式 PPT；不覆盖历史 Word/PPT/Excel。
11. **监听器本身禁止调用 Claude 或 DeepSeek**：实时监听只做本地文件事件判定，
    **只有正式 run 才调用模型**。
12. 遇到不确定信息，标记【待人工确认】，**不要猜**。
